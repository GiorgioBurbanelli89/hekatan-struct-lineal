Diapositiva 11b · Bloque 4 — formato de intercambio

Estructura interna del archivo .e2k de ETABS

Texto plano. Cada sección empieza con $. Un .e2k bien escrito se abre en ETABS, SAP, OpenSees y Hekatan sin convertir.

Por qué texto plano

Mientras que el formato nativo .EDB de ETABS es binario (rápido, propietario), el .e2k es texto ASCII con secciones delimitadas — equivalente a JSON pero específico para FEM estructural. Ventajas:

  • Diff y merge con git — versionable.
  • Editable a mano con cualquier editor (debugging rápido).
  • Round-trip: cualquier programa que lo parsea correctamente lo reproduce.
  • Estándar de facto en la industria: ETABS, SAP2000 (S2K), SAFE (F2K) usan la misma sintaxis.

Las 24 secciones canónicas (en orden)

$ PROGRAM INFORMATION

1. Identificación del programa que generó el archivo

  PROGRAM  "ETABS"  VERSION "21.2.0"
Hekatan emite "ETABS" VERSION "22.6.0" aquí.
$ CONTROLS

2. Sistema de unidades y título

  UNITS  "Tonf"  "m"  "C"
  TITLE2  "Mi modelo - Hekatan export"
Las unidades aplican a TODOS los valores numéricos. El orden es fuerza · longitud · temperatura.
$ STORIES - IN SEQUENCE FROM TOP

3. Pisos del edificio (de arriba hacia abajo)

  STORY "Roof"   HEIGHT 3.0  MASTERSTORY "Yes"
  STORY "Story3" HEIGHT 3.0  MASTERSTORY "No"
  STORY "Story2" HEIGHT 3.0
  STORY "Base"   ELEV 0
Cada nodo se identifica luego por (POINT, STORY). MASTERSTORY indica si es plantilla para los demás.
$ GRIDS

4. Líneas de grilla X e Y

  GRID "G1"  GRIDTYPE "Cartesian"
  GRID "G1"  X1  -10  X2  20  Y1  -8  Y2  16
  GRID "G1"  GRIDLINETYPE "X" ID "A" ORDINATE 0
  GRID "G1"  GRIDLINETYPE "Y" ID "1" ORDINATE 0
Solo para visualización en ETABS. Hekatan no usa grids (modela por coordenadas directas).
$ DIAPHRAGM NAMES

5. Definición de diafragmas (rígido / semirígido)

  DIAPHRAGM "D1"   TYPE RIGID
  DIAPHRAGM "D2"   TYPE SEMIRIGID
Acopla nodos del piso con constraint master-slave. Hekatan aún no implementa este constraint (ver slide 15).
$ MATERIAL PROPERTIES

6. Propiedades de cada material

  MATERIAL  "A572Gr50"  TYPE "Steel"  GRADE "Grade 50"  WEIGHTPERVOLUME 7.849
  MATERIAL  "A572Gr50"  SYMTYPE "Isotropic"  E 2.04E+07  U 0.3  A 1.17E-05
  MATERIAL  "A572Gr50"  FY 35153  FU 45699
  MATERIAL  "Conc4000"  TYPE "Concrete"  WEIGHTPERVOLUME 2.4
  MATERIAL  "Conc4000"  SYMTYPE "Isotropic"  E 2,549,000  U 0.2  A 1E-05
  MATERIAL  "Conc4000"  FC 2,812
$E$ en tonf/m², $\gamma$ en tonf/m³. U = ν Poisson. A = $\alpha$ térmico. Hekatan detecta Steel vs Concrete por valor de E.
$ FRAME SECTIONS

7. Perfiles de columnas y vigas

  FRAMESECTION  "W14X84"  MATERIAL "A572Gr50"  SHAPE "Steel I/Wide Flange"  D 0.358  B 0.262  TF 0.0193  TW 0.0114
  FRAMESECTION  "C30x30"  MATERIAL "Conc4000"  SHAPE "Concrete Rectangular"  D 0.30  B 0.30
  FRAMESECTION  "HSS300x300x12"  MATERIAL "A572Gr50"  SHAPE "Steel Tube"  D 0.30  B 0.30  TF 0.012  TW 0.012
Tipos comunes: Steel I/Wide Flange, Steel Tube, Steel Pipe, Concrete Rectangular, Concrete Circle. ETABS calcula automáticamente A, I, J, S desde D, B, TF, TW.
$ POINT COORDINATES

8. Nodos en planta (solo X, Y)

  POINT "1"   0     0
  POINT "2"   5.0   0
  POINT "3"   5.0   4.0
  POINT "4"   0     4.0
La Z (altura) NO se especifica aquí — viene del STORY al que se asigne el punto. Por eso un mismo POINT "1" puede representar nodos en diferentes pisos.
$ LINE CONNECTIVITIES

9. Conectividad de frames

  LINE  "C1"  COLUMN  "1"  "1"  1     # Columna: pt1=pt2, nStories=1
  LINE  "B1"  BEAM    "1"  "2"  0     # Viga: del pt1 al pt2 en el mismo story
  LINE  "D1"  BRACE   "1"  "2"  1     # Diagonal
Para columnas, ambos extremos usan el mismo POINT (la Z viene de los STORYs consecutivos). Para vigas, los dos POINTs son distintos.
$ AREA CONNECTIVITIES

10. Conectividad de elementos shell (Q4)

  AREA  "F1"  FLOOR  4  "1"  "2"  "3"  "4"  0  0  0  0     # Losa
  AREA  "W1"  PANEL  4  "1"  "2"  "2"  "1"  1  1  0  0     # Muro
Losas (FLOOR) usan 4 puntos distintos en el mismo story. Muros (PANEL) usan 2 puntos repetidos con altura por nStories.
$ POINT ASSIGNS

11. Restricciones (apoyos) y masas adicionales

  POINTASSIGN  "1"  "Base"  RESTRAINT "UX UY UZ RX RY RZ"     # Empotrado
  POINTASSIGN  "2"  "Base"  RESTRAINT "UX UY UZ"               # Articulado
  POINTASSIGN  "1"  "Roof"  ADDMASS  500                       # Masa adicional
Combinaciones: "UX UY UZ" = articulado, "UX UY UZ RX RY RZ" = empotrado, "UZ" = solo restringe vertical.
$ LINE ASSIGNS

12. Asignar sección y modificadores a frames

  LINEASSIGN  "C1"  "Story1"  SECTION "W14X84"  ANG 0  RIGIDZONE 1  RELEASE "M2I M3I"
              MAXSTASPC 0.4  AUTOMESH "YES"  MESHATINTERSECTIONS "YES"
              PROPERTYMODIFIERS "AREA 0.5 I33 0.7 I22 0.7"
El frame en story X1 hereda sección, releases (rótulas), modificadores de inercia, etc. Un mismo LINE en distintos stories puede tener secciones diferentes.
$ LOAD PATTERNS

13. Casos de carga base

  LOADPATTERN "Dead"  TYPE "Dead"   SELFWEIGHT 1
  LOADPATTERN "Live"  TYPE "Live"   SELFWEIGHT 0
  LOADPATTERN "Ex"    TYPE "Quake"  SELFWEIGHT 0  AUTOLOAD "ASCE 7-22"
Si SELFWEIGHT=1, ETABS suma el peso propio automáticamente. Hekatan exporta SELFWEIGHT 0 para evitar doble conteo (ya incluye peso propio como POINTLOAD).
$ POINT OBJECT LOADS

14. Cargas puntuales en nodos

  POINTLOAD  "5"  "Roof"  "Dead"  TYPE "FORCE"   FX 0  FY 0  FZ -50
  POINTLOAD  "5"  "Roof"  "Dead"  TYPE "MOMENT"  MX 0  MY 12  MZ 0
Cada nodo (POINT, STORY) puede recibir múltiples cargas. FZ negativo = hacia abajo. Las unidades coinciden con las del header CONTROLS.
$ FRAME OBJECT LOADS

15. Cargas distribuidas en frames

  LINELOAD  "B1"  "Story1"  "Dead"  TYPE "DISTRIBUTED"  DIR "Z"  FSTART -2.5  FEND -2.5
  LINELOAD  "B1"  "Story1"  "Live"  TYPE "DISTRIBUTED"  DIR "Z"  FSTART -1.0  FEND -1.0
Distribuidas constantes (FSTART = FEND) o trapezoidales. Hekatan las convierte a nodal equivalente.
$ SHELL OBJECT LOADS

16. Cargas distribuidas en shells

  SHELLLOAD  "F1"  "Story2"  "Dead"  TYPE "UNIFORM"  DIR "GRAV"  VAL -3.5
VAL negativo = hacia abajo. DIR "GRAV" = global Z gravedad.
$ MASS SOURCE

17. Cómo construir M para análisis modal

  MASSSOURCE  "MS"  ELEMENTS "Yes"  ADDITIONAL "Yes"  LOADS "Yes"
  MASSSOURCE  "MS"  LOADPAT "Dead"  SF 1
  MASSSOURCE  "MS"  LOADPAT "Live"  SF 0.25
La masa sale del peso propio (ELEMENTS) + masas extras (ADDITIONAL) + parte de cargas vivas (LOADS · SF 0.25 = 25% de la viva).
$ LOAD CASES

18. Tipos de análisis a correr

  LOADCASE "Dead"   TYPE "Linear Static"  INITCOND "PRESET"
  LOADCASE "Dead"   LOADPAT "Dead"  SF 1
  LOADCASE "Modal"  TYPE "Modal - Eigen"  MAXMODES 12  MINMODES 1
  LOADCASE "Ex_RS" TYPE "Response Spectrum"  MODALCASE "Modal"  MODALCOMBO "CQC"
Cada LoadCase es una corrida independiente. Linear Static = $K\,u = F$. Modal = $(K-\omega^2 M)\phi = 0$. Response Spectrum = combinación modal con $S_a(T)$.
$ LOAD COMBINATIONS

19. Combinaciones de carga normativas

  COMBO "1.4D"      TYPE "Linear Add"
  COMBO "1.4D"      LOADCASE "Dead"  SF 1.4
  COMBO "1.2D+1.6L" TYPE "Linear Add"
  COMBO "1.2D+1.6L" LOADCASE "Dead"  SF 1.2
  COMBO "1.2D+1.6L" LOADCASE "Live"  SF 1.6
Combinaciones ASCE 7-22 / NEC-SE-CG. Pueden ser Linear Add (simple), SRSS, Envelope. Hekatan emite las dos básicas para que ETABS pueda diseñar.

Cierre del archivo

  END
$ END OF MODEL FILE

Línea final obligatoria. Sin ella, ETABS rechaza el archivo.

Ejemplo concreto · Paz Ej. 13.1 (Space Frame 3D)

El benchmark del libro de Paz cap. 13.7 (5 nodos · 4 vigas radiando · F=5000 lb step en Z) se expresa en .e2k así. Este archivo abre directamente en ETABS 19+ y está versionado en Etabs Powershell/Paz_13_1.e2k:

Geometría · 5 nodos · 4 elementos 
$ POINT COORDINATES
  POINT "1"  0       0
  POINT "2"  0       5.08
  POINT "3"  -5.08   0

$ LINE CONNECTIVITIES
  LINE "E1"  BEAM    "1"  "2"  0    $ vertical Y → BEAM en planta Story1
  LINE "E2"  COLUMN  "1"  "1"  1    $ vertical Z+ → COLUMN Story1→Story2
  LINE "E3"  BEAM    "1"  "3"  0    $ horizontal X → BEAM en Story1
  LINE "E4"  COLUMN  "1"  "1"  1    $ vertical Z- → COLUMN Base→Story1
El truco para mapear el espacio frame de Paz (eje Y up) a ETABS (eje Z up) es swappear Y↔Z: 200 in = 5.08 m. Los 4 nodos fijos se vuelven RESTRAINTs y el central queda libre.
Material acero E=30·10⁶ psi → 2.11·10⁷ tonf/m² 
  MATERIAL "STEEL"  TYPE "Steel"  GRADE "Grade 50"  WEIGHTPERVOLUME 7.85
  MATERIAL "STEEL"  SYMTYPE "Isotropic"  E 21093744  U 0.25  A 1.17E-05
G = 12·10⁶ psi y E/G = 2.5 ⇒ ν = 0.25 (no 0.3). La densidad es realista para mostrar el modelo en ETABS — la masa de Paz se valida en Hekatan, no aquí.
Secciones equivalentes a A · I del libro 
  FRAMESECTION "SEC1"  MATERIAL "STEEL"  SHAPE "Concrete Rectangular"  D 0.18 B 0.18  $ A=50, I=200 in⁴
  FRAMESECTION "SEC2"  MATERIAL "STEEL"  SHAPE "Concrete Rectangular"  D 0.135 B 0.135 $ A=28, I=64 in⁴
Calculamos b·h tal que b·h = A y b·h³/12 = I: para A=50 in², I=200 in⁴ → 0.18 m × 0.18 m.
Restricciones · 4 nodos empotrados + 1 carga puntual 
  POINTASSIGN "2"  "Story1"  RESTRAINT "UX UY UZ RX RY RZ"
  POINTASSIGN "3"  "Story1"  RESTRAINT "UX UY UZ RX RY RZ"
  POINTASSIGN "1"  "Story2"  RESTRAINT "UX UY UZ RX RY RZ"
  POINTASSIGN "1"  "Base"    RESTRAINT "UX UY UZ RX RY RZ"

  POINTLOAD "1"  "Story1"  TYPE "FORCE"  LC "USER"  FX 0 FY -2.268 FZ 0  $ 5000 lb = 22.24 kN = 2.268 tonf
El nodo central (POINT "1" en Story1) queda libre — recibe la carga step de 5000 lb (22.24 kN ≈ 2.268 tonf-fuerza).

El .e2k es ~25× más liviano que el .EDB porque omite resultados, mallas auto-generadas y metadata gráfica. Para distribuir por correo o git, siempre prefieras .e2k.

Para llevarse: el .e2k no es magia binaria — es texto plano con 19 secciones bien definidas. Si entiendes la sintaxis, puedes leer / escribir / parchar archivos a mano. Hekatan implementa parseE2k() y exportE2k() en TypeScript siguiendo exactamente esta estructura. El round-trip Hekatan ↔ ETABS es solo manipulación de strings disciplinada.
