Estructura del archivo .f2k de SAFE

SAFE = Slab Analysis by the Finite Element Method. Específico para cimentaciones y losas con interacción suelo-estructura. Similar al .e2k pero con bloques propios de Winkler.

Para qué usar SAFE (no ETABS)

  • Losas de cimentación sobre resortes Winkler 3D (zapatas, plateas, losas de fundación).
  • Losas de piso con análisis detallado de momentos por punzonamiento.
  • Diseño de armadura para flexión y corte siguiendo ACI 318, ACI 350, NTE.
  • No es para edificios completos — SAFE solo modela el plano horizontal, ETABS hace el edificio entero.

Hekatan Struct Lineal exporta .f2k desde los ejemplos zapata-aislada, zapata-viga-amarre (toggle en panel Cimentación (diseño + SAFE F2K)).

Las 16 secciones del .f2k (en orden)

$ PROGRAM INFORMATION

1. Identificación

  PROGRAM  "SAFE"  VERSION "21.0.0"
Hekatan emite ProgramName=SAFE Version=20.3.0.
$ CONTROLS

2. Unidades y nombre del modelo

  UNITS  "Tonf"  "m"  "C"
  TITLE  "Zapata aislada NEC-SE-GC"
Mismo formato que el .e2k.
$ MATERIAL PROPERTIES

3. Hormigón y acero (mismo formato e2k)

  MATERIAL  "Conc4000"  TYPE "Concrete"  WEIGHTPERVOLUME 2.4
  MATERIAL  "Conc4000"  SYMTYPE "Isotropic"  E 2,549,000  U 0.2
  MATERIAL  "Conc4000"  FC 2,812
$ SLAB PROPERTIES

4. Espesor y tipo de losa

  SLABPROP  "Zapata50"   TYPE "Mat"   MATERIAL "Conc4000"  THICKNESS 0.50
  SLABPROP  "Losa20"     TYPE "Slab"  MATERIAL "Conc4000"  THICKNESS 0.20
Tipos: Slab (losa de piso), Mat (platea de cimentación), Footing (zapata aislada), Drop (capitel).
$ COLUMN PROPERTIES

5. Columnas que llegan a la losa (cargan punzonamiento)

  COLUMNPROP  "C30x30"  MATERIAL "Conc4000"  WIDTH 0.30  DEPTH 0.30  HEIGHT 3.0
SAFE usa la columna solo como geometría para análisis de punzonamiento. El cuerpo de la columna no se modela.
$ POINT COORDINATES

6. Nodos en plano X-Y

  POINT "1"   0     0    0
  POINT "2"   3.0   0    0
  POINT "3"   3.0   3.0  0
  POINT "4"   0     3.0  0
A diferencia del .e2k, SAFE no usa STORYs — coloca los nodos directamente con (X, Y, Z). La Z suele ser 0 (nivel de cimentación).
$ AREA OBJECTS

7. Losas como elementos área

  AREA  "F1"  TYPE "Floor"     POINT1 "1"  POINT2 "2"  POINT3 "3"  POINT4 "4"
  AREA  "Z1"  TYPE "Footing"   POINT1 "5"  POINT2 "6"  POINT3 "7"  POINT4 "8"
Cada AREA es un cuadrilátero o triángulo. SAFE las malla automáticamente en Q4 / T3 según parámetros.
$ POINT OBJECTS

8. Cargas puntuales (típicamente columnas que descargan a la losa)

  POINT "C1"  X 1.5  Y 1.5  Z 0  COLUMN "C30x30"
SAFE colapsa la columna a un punto sobre la losa. Las reacciones se transfieren como carga puntual.
$ AREA ASSIGNS

9. Asignar propiedades a cada AREA

  AREAASSIGN  "F1"  SECTION "Losa20"  EDGEDISCRET 0.30  AUTOMESH "YES"
  AREAASSIGN  "Z1"  SECTION "Zapata50" EDGEDISCRET 0.20
EDGEDISCRET = tamaño de malla deseado en el borde. Más fino en zonas críticas.
$ SOIL PROPERTIES

10. Suelo Winkler — coeficiente de balasto

  SOILPROP  "S1"  TYPE "Winkler"  MODULUS 1500       # k_s = 1500 tonf/m³
  SOILPROP  "S2"  TYPE "Winkler"  MODULUS 800        # arena suelta
  SOILPROP  "S3"  TYPE "Winkler"  MODULUS 5000       # roca
Esto es lo que distingue al .f2k del .e2k. ETABS no tiene Winkler nativo — SAFE sí. Hekatan usa el mismo modelo: $k_s$ multiplicado por área tributaria de cada nodo da la rigidez del resorte vertical.
$ AREA SPRINGS

11. Asignación de Winkler a las zapatas

  AREASPRING  "Z1"  SOIL "S2"  DIR "GRAV"  COMPRESSIONONLY "Yes"
COMPRESSIONONLY="Yes" = el resorte solo trabaja a compresión (la zapata no "tira" del suelo cuando se levanta). En Hekatan, esto se modela con springs activos solo si $u_z < 0$.
$ POINT ASSIGNS

12. Restricciones puntuales (poco usadas en SAFE)

  POINTASSIGN  "1"  RESTRAINT "UX UY"
SAFE típicamente no usa apoyos rígidos — toda la rigidez vertical viene de Winkler. Apoyos solo para fijar traslación lateral en algún punto (rotación rígida en plano).
$ LOAD PATTERNS

13. Casos de carga (igual que e2k)

  LOADPATTERN "Dead"  TYPE "Dead"   SELFWEIGHT 1
  LOADPATTERN "Live"  TYPE "Live"   SELFWEIGHT 0
  LOADPATTERN "Wind"  TYPE "Wind"
$ POINT LOADS

14. Cargas de columnas

  POINTLOAD  "C1"  "Dead"  TYPE "FORCE"   FZ -50
  POINTLOAD  "C1"  "Dead"  TYPE "MOMENT"  MX 1.5  MY -2.3
  POINTLOAD  "C1"  "Live"  TYPE "FORCE"   FZ -25
Bajada de cargas desde el ETABS del edificio. FZ negativo = compresión sobre la zapata.
$ AREA LOADS

15. Cargas distribuidas en losas

  AREALOAD  "F1"  "Dead"  TYPE "UNIFORM"  DIR "GRAV"  VAL -0.30   # peso propio + acabados
  AREALOAD  "F1"  "Live"  TYPE "UNIFORM"  DIR "GRAV"  VAL -0.25   # 250 kgf/m²
$ DESIGN PREFERENCES

16. Norma de diseño y armadura

  DESIGN  CODE "ACI 318-19"
  DESIGN  REBARSIZE "#5"  COVER 0.05  FY 4200  PHI_FLEX 0.9
SAFE diseña la armadura automáticamente bajo la norma elegida. ACI 318 (US), Eurocódigo 2, NTE E.060 (Perú), NEC-SE-HM (Ecuador).

Diferencias clave .f2k vs .e2k

Aspecto.e2k (ETABS).f2k (SAFE)
Geometría3D con STORYs2D plano X-Y (Z = 0 típico)
FramesSí (COLUMN/BEAM/BRACE)No (solo COLUMN como punto)
ShellsSí (FLOOR/PANEL)Sí (Floor/Mat/Footing)
WinklerNo nativo$ SOIL PROPERTIES + $ AREA SPRINGS
DiseñoVigas y columnasLosas (flexión + punzonamiento)
Análisis modalSíSí pero raro (típicamente static)

// hekatan-struct-lineal/examples/src/shared/f2kExporter.ts

  nodes,                    // [[x,y,0], ...]
  elements,                 // [[i,j,k,l], ...]  Q4 quads
  nodeInputs,               // { supports, loads, springs }
  elementInputs,            // { thicknesses, materialIDs }
  soilProperties,           // { ks_kNm3, soilType }

}) => "string .f2k completo"

Botón en el workspace: Cimentación (diseño + SAFE F2K) → toggle 📤 Exportar .f2k.

Mensaje: el .f2k es como el .e2k pero especializado en cimentaciones. Lo que distingue es la sección $ SOIL PROPERTIES + $ AREA SPRINGS (Winkler). Si tu modelo es solo zapatas y losas, exportá a SAFE; si es edificio completo, a ETABS.
