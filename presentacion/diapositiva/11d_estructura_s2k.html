Estructura del archivo .s2k de SAP2000

SAP2000 = solver general de estructuras (puentes, torres, presas, naves). El .s2k es tabular con TABLES delimitadas, no por $.

Para qué usar SAP2000 (no ETABS)

  • Puentes — vigas continuas, atirantados, colgantes con cables.
  • Torres y antenas — celosías 3D con muchos diagonales.
  • Estructuras industriales — galpones, naves, silos.
  • Presas y muros de retención — sólidos H8 con interacción suelo.
  • Análisis no lineales avanzados — pushover, time-history grandes.
  • SAP no asume "edificio" — no obliga a tener STORYs. Es 3D libre.

Hekatan Struct Lineal exporta .s2k desde el panel SAP del workspace para cualquier ejemplo no-zapata.

Sintaxis: TABLES en lugar de secciones $

El .s2k usa formato tabular. Cada bloque empieza con TABLE: "Nombre" seguido de filas con Campo=Valor separados por espacios:

TABLE:  "PROGRAM CONTROL"
   ProgramName=SAP2000  Version=24.0.0  CurrUnits="Tonf, m, C"

TABLE:  "JOINT COORDINATES"
   Joint=1   CoordSys=GLOBAL   CoordType=Cartesian   XorR=0    Y=0    Z=0
   Joint=2   CoordSys=GLOBAL   CoordType=Cartesian   XorR=5    Y=0    Z=0
   Joint=3   CoordSys=GLOBAL   CoordType=Cartesian   XorR=5    Y=4    Z=3

Esto es muy diferente al .e2k de ETABS. Cada TABLE es independiente.

Las 18 TABLES principales del .s2k

TABLE 1

"PROGRAM CONTROL" — header

TABLE:  "PROGRAM CONTROL"
   ProgramName=SAP2000  Version=24.0.0
   ProgLevel="Plus"     LicenseOS=No
   CurrUnits="Tonf, m, C"
Hekatan emite ProgramName=SAP2000 Version=24.1.0.
TABLE 2

"COORDINATE SYSTEMS" — sistema(s) de referencia

TABLE:  "COORDINATE SYSTEMS"
   Name=GLOBAL  Type=Cartesian  X=0  Y=0  Z=0  AboutZ=0  AboutY=0  AboutX=0
SAP soporta múltiples sistemas de coordenadas (cilíndrico, esférico). Hekatan usa solo GLOBAL cartesiano.
TABLE 3

"JOINT COORDINATES" — nodos en 3D libre

TABLE:  "JOINT COORDINATES"
   Joint=1  CoordSys=GLOBAL  CoordType=Cartesian  XorR=0    Y=0    Z=0
   Joint=2  CoordSys=GLOBAL  CoordType=Cartesian  XorR=5    Y=0    Z=3
   Joint=3  CoordSys=GLOBAL  CoordType=Cartesian  XorR=10   Y=2    Z=6
X, Y, Z explícitos — no hay STORYs como en .e2k. Esto permite geometrías 3D arbitrarias (puentes inclinados, torres curvas).
TABLE 4

"MATERIAL PROPERTIES 02 - BASIC MECHANICAL"

TABLE:  "MATERIAL PROPERTIES 02 - BASIC MECHANICAL PROPERTIES"
   Material=A572Gr50  Type=Steel       UnitWeight=7.849  E1=2.04E+07  G12=7.85E+06  U12=0.3
   Material=Conc4000  Type=Concrete    UnitWeight=2.4    E1=2,549,000 G12=1,062,000 U12=0.2
Más detallado que el .e2k: SAP separa propiedades isotrópicas, anisotrópicas, ortotrópicas en TABLES distintas.
TABLE 5

"FRAME SECTION PROPERTIES" — perfiles

TABLE:  "FRAME SECTION PROPERTIES 01 - GENERAL"
   SectionName=W14X84  Material=A572Gr50  Shape="I/Wide Flange"
   t3=0.358  t2=0.262  tf=0.0193  tw=0.0114  Area=0.0156  TorsConst=2.66E-06  I33=4.16E-04  I22=4.16E-05
SAP además acepta secciones generales (custom) con A, I, J, S directos sin shape. Útil para secciones no estándar.
TABLE 6

"FRAME CONNECTIVITY" — frames como pares de nodos

TABLE:  "CONNECTIVITY - FRAME"
   Frame=1   JointI=1   JointJ=2
   Frame=2   JointI=2   JointJ=3
   Frame=3   JointI=1   JointJ=3
A diferencia del .e2k, no hay distinción COLUMN / BEAM / BRACE — todos son frame. La orientación se define con vector aparte.
TABLE 7

"FRAME ASSIGNMENTS" — sección a cada frame

TABLE:  "FRAME SECTION ASSIGNMENTS"
   Frame=1   AutoSelect=N.A.  AnalSect=W14X84   DesignSect=W14X84
   Frame=2   AutoSelect=N.A.  AnalSect=W14X84   DesignSect=W14X84
TABLE 8

"AREA SHAPES" — Shells (Q4 / Q8 / T3 / T6)

TABLE:  "CONNECTIVITY - AREA"
   Area=1   NumJoints=4   Joint1=10  Joint2=11  Joint3=12  Joint4=13
   Area=2   NumJoints=3   Joint1=20  Joint2=21  Joint3=22
SAP soporta Q4, Q8, T3, T6 según el campo NumJoints. Hekatan usa Q4 (4 nodos) por defecto.
TABLE 9

"SOLID SHAPES" — Sólidos H8 (sí, SAP los maneja)

TABLE:  "CONNECTIVITY - SOLID"
   Solid=1  J1=100 J2=101 J3=102 J4=103 J5=104 J6=105 J7=106 J8=107
SAP soporta H8 (8 nodos), H20, T4 (tetraedros). Hekatan exporta H8 desde los ejemplos sólidos.
TABLE 10

"JOINT RESTRAINTS" — apoyos

TABLE:  "JOINT RESTRAINT ASSIGNMENTS"
   Joint=1   U1=Yes  U2=Yes  U3=Yes  R1=Yes  R2=Yes  R3=Yes        # Empotrado
   Joint=2   U1=Yes  U2=Yes  U3=Yes  R1=No   R2=No   R3=No         # Articulado
U1, U2, U3 = traslaciones X, Y, Z. R1, R2, R3 = rotaciones.
TABLE 11

"LINK / SUPPORT PROPERTIES" — links no lineales

TABLE:  "LINK PROPERTY DEFINITIONS"
   Link=Spring1   PropType=Linear   DOF=U3   Effective="Yes"   k=1500
SAP modela Winkler con links (resortes 1D) — distinto a SAFE que usa AREA SPRINGS. Hekatan los traduce.
TABLE 12

"LOAD PATTERN DEFINITIONS"

TABLE:  "LOAD PATTERN DEFINITIONS"
   LoadPat=Dead   DesignType=DEAD   SelfWtMult=1
   LoadPat=Live   DesignType=LIVE   SelfWtMult=0
   LoadPat=Ex     DesignType=QUAKE  SelfWtMult=0   AutoLoad="ASCE 7-22"
TABLE 13

"JOINT LOADS - FORCE"

TABLE:  "JOINT LOADS - FORCE"
   Joint=5   LoadPat=Dead   F1=0    F2=0    F3=-50    M1=0    M2=12   M3=0
F1, F2, F3 = fuerzas globales X, Y, Z. M1, M2, M3 = momentos.
TABLE 14

"FRAME LOADS - DISTRIBUTED"

TABLE:  "FRAME LOADS - DISTRIBUTED"
   Frame=2   LoadPat=Dead  CoordSys=GLOBAL  Type=Force  Dir=Z  RelDistA=0  RelDistB=1  ValA=-2.5  ValB=-2.5
Distribuidas con dos puntos (RelDistA/B en [0,1]) para crear trapezoidales.
TABLE 15

"AREA LOADS - UNIFORM"

TABLE:  "AREA LOADS - UNIFORM"
   Area=10   LoadPat=Dead   CoordSys=GLOBAL   Dir=GravProj   UnifLoad=-3.5
TABLE 16

"MASS SOURCE"

TABLE:  "MASS SOURCE"
   FromElem=Yes   FromAddedMass=Yes   FromLoadPat=Yes
   LoadPat1=Dead     SF1=1
   LoadPat2=Live     SF2=0.25
TABLE 17

"LOAD CASE DEFINITIONS"

TABLE:  "LOAD CASE DEFINITIONS"
   Case=Dead    Type=LinStatic     InitialCond=Zero
   Case=Modal   Type=LinModal      MaxNumModes=12   MinNumModes=1
   Case=Ex_RS   Type=LinRespSpec   ModalCase=Modal  ModalCombo=CQC
SAP tiene MUCHOS tipos: LinStatic, LinModal, LinRespSpec, NonStatic (pushover), DirHistNonlinear (time-history no-lineal), Buckling, etc.
TABLE 18

"COMBINATION DEFINITIONS"

TABLE:  "COMBINATION DEFINITIONS"
   ComboName=1.4D     ComboType=LinAdd   CaseType=LinStatic   CaseName=Dead    ScaleFactor=1.4
   ComboName=1.2D+1.6L ComboType=LinAdd  CaseType=LinStatic   CaseName=Dead    ScaleFactor=1.2
   ComboName=1.2D+1.6L ComboType=LinAdd  CaseType=LinStatic   CaseName=Live    ScaleFactor=1.6

Diferencias clave .s2k vs .e2k

Aspecto.e2k (ETABS).s2k (SAP2000)
SintaxisBloques con $TABLES con campo=valor
GeometríaSTORYs + POINT (X,Y)JOINT (X,Y,Z) libre 3D
FramesCOLUMN/BEAM/BRACESolo "frame", orientación con vector
SólidosNoH8, H20, T4

DiseñoEdificios (vigas, columnas)General (puentes, torres)
Cuándo usarEdificios convencionalesEstructuras singulares

.s2k es ligeramente más verboso que .e2k porque cada TABLE repite los nombres de campo. A cambio, es más auto-descriptivo y no depende del orden.

Resumen de los 3 formatos: ETABS (.e2k) para edificios, SAP2000 (.s2k) para todo lo demás, SAFE (.f2k) para cimentaciones. Hekatan Struct Lineal exporta a los tres formatos desde el mismo modelo — el round-trip es garantizado para validación cruzada con cualquier suite CSI.
